> **更新日期**: 2026-04-05

## 当前问题：开环摇杆不转 — M1_UpdateCtrlRef 覆盖 AngleDelta

### 现象

- 通信已通 (TX/RX 正常，Iq=100mA 已生效)
- 拖摇杆电机不转，AngleDelta 被覆盖为 0

### 根因

`main.c` 第 1601-1611 行 `M1_UpdateCtrlRef()` 开环分支：

```c
g_M1_Idq_Ref.d = MA_TO_Q15(0);              // Id 写死 0
g_M1_Idq_Ref.q = MA_TO_Q15(g_M1_Iq_Ref_mA); // Iq 从协议读 ✅
g_M1_AngleDelta_Target = RPM_to_AngleDelta(  // ❌ 用 RPM_Cmd 覆盖!
        g_M1_RPM_Cmd, M1_POLE_PAIRS, ENC_ISR_FREQ_HZ);
```

上位机 SET_IQ_REF 写了 `g_M1_AngleDelta_Target`，但下一个 while(1) 迭代 `M1_UpdateCtrlRef()` 立即用 `RPM_to_AngleDelta(g_M1_RPM_Cmd=0)` 把它覆盖成 0。M2 同理。

### 修改方案 (二选一)

**方案 A (推荐)：上位机改写 RPM_Cmd 而非 AngleDelta**

不改固件。上位机摇杆值换算成 RPM 写入 `g_M1_RPM_Cmd`，让 `M1_UpdateCtrlRef()` 自己算 AngleDelta。

需要新增协议命令或复用 SET_MOTION 的 M1_delta 字段写 RPM_Cmd。

**方案 B：固件跳过覆盖**

在 `M1_UpdateCtrlRef()` 中，当协议已经写了 AngleDelta 时不再覆盖。简单做法：增加一个标志位 `g_M1_AngleDelta_FromProtocol`，SET_IQ_REF 收到 12B payload 时置 1，`M1_UpdateCtrlRef` 检查此标志跳过 RPM_to_AngleDelta 计算。

```c
// M1_UpdateCtrlRef() 开环分支修改:
if (g_M1_CtrlMode == MODE_OPEN_LOOP && ...) {
    g_M1_Idq_Ref.d = MA_TO_Q15(0);
    g_M1_Idq_Ref.q = MA_TO_Q15(g_M1_Iq_Ref_mA);
    if (!g_M1_AngleDelta_FromProtocol) {           // 新增判断
        g_M1_AngleDelta_Target = RPM_to_AngleDelta(
                g_M1_RPM_Cmd, M1_POLE_PAIRS, ENC_ISR_FREQ_HZ);
    }
}

// comm_protocol.c handle_set_iq_ref() 中 AngleDelta 解析处:
if (len >= 12) {
    ...
    g_M1_AngleDelta_FromProtocol = 1;  // 新增
    g_M2_AngleDelta_FromProtocol = 1;  // 新增
}

// 看门狗/超时归零时清除:
g_M1_AngleDelta_FromProtocol = 0;
g_M2_AngleDelta_FromProtocol = 0;
```

M2 同理。

### 同时注意：Id 也被写死 0

开环分支 `g_M1_Idq_Ref.d = MA_TO_Q15(0)` 把 Id 写死为 0，上位机发的 Id 值（写入 `g_M1_Id_Hold_mA`）在开环下不生效，因为开环直接写 `Idq_Ref.d = 0`，不走 Id 自适应。

如果开环需要 Id > 0（某些电机需要），需要改为：
```c
g_M1_Idq_Ref.d = MA_TO_Q15(g_M1_Id_Hold_mA);  // 替代写死 0
```
